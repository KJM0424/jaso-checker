# 1단계: 조사

목표: `2_기업분석_MMDD.md`(양식은 formats.md). 하위 에이전트 두 개를 동시에 띄운다. 결과를 합쳐 쓰고, 끝나면 **확인 1**에서 멈춘다.

## 에이전트 A: 공식 자료

지시문(그대로 전달, 괄호는 채운다):

```
한국 취업 준비자의 자소서 작성을 위한 기업·직무 조사. 한국어. 이모지 금지. 주장마다 URL과 확인 날짜.
기업: (기업) / 직무: (직무) / 공고 원문: (1_공고_전형.md 내용)
조사할 것:
1. 공고의 요구 역량·우대사항을 항목별로 풀어 쓰고, 각 항목이 실무에서 무엇을 뜻하는지(채용 페이지, 직무 소개, 기술 블로그 근거).
2. 회사 사업과 최근 6개월 뉴스: 신사업, AI·데이터 관련 프로젝트, 조직 변화, 실적. 보도자료와 주요 언론만.
3. 기술 블로그·채용 페이지·공개 발표에서 확인되는 기술 스택과 개발 문화.
4. 인재상·핵심가치 원문과 출처.
5. DART 사업보고서(상장사면): 사업 부문, AI·디지털 투자 언급.
6. 지원동기에 쓸 수 있는 "이 회사만의 구체 사실" 후보 5개. 경쟁사에도 똑같이 쓸 수 있는 일반론은 제외. 공지·입찰 공고·공시 같은 1차 자료를 보도자료 요약보다 우선하고, 다른 지원자도 쉽게 찾을 사실에는 "흔함"이라고 표시한다.
7. 공고에 AI 활용 규정(금지, 고지 의무, 검증 예고)이 있는지. 있으면 원문을 옮긴다.
출력: 번호 절 7개, 각 항목 `- 내용 — URL (확인 YYYY-MM-DD)`. 못 찾은 것은 "찾지 못함: 어디를 봤나".
```

하위 에이전트를 쓸 수 없는 환경이면 같은 지시문의 항목을 직접 WebSearch로 조사한다. 가상 기업이거나 첫 검색에서 회사 자료가 전혀 나오지 않으면 검색을 반복하지 않고 "찾지 못함"으로 적는다.

## 에이전트 B: 비공식 자료 (참고용)

```
같은 기업·직무에 대한 커뮤니티 자료 조사. 한국어. 이모지 금지. 참고용이며 자소서 근거로 쓰지 않는다.
찾을 것: 잡플래닛·블라인드의 조직문화와 직무 평, 합격 자소서 공유 사이트의 같은 직무 합격 자소서 구조, 면접 후기에서 자소서 관련 질문.
출력: 항목마다 `- 내용 — URL (확인 날짜) (신뢰도: 자칭 담당자/익명/플랫폼 공식)`. 찾지 못하면 그렇게 쓴다.
```

## 합치기

1. `공고 요구 × 장면 대응` 표: 공고의 요구·우대 항목마다 `07_경험뱅크/00_색인.md`에서 대응 장면을 찾는다. 근거 강도: **강** = 장면 `상태`가 `확정`이고 `본인행동`에 `[원본: …]` 표시가 있음 / **중** = `본인확인필요`지만 `[원본: …]` 또는 `[분석: …]` 표시가 있음 / **없음** = 대응 장면이 없음. 판단하려면 색인만 보지 말고 후보 장면의 파일을 연다. 대응 장면이 없으면 "없음"이라고 쓴다. 지어내지 않는다.
2. `지원동기용 고유 사실`: 에이전트 A의 6번에서 출처가 있는 것만 3~5개. 0개면 지원동기 문항에 경고를 남긴다.
3. `담당자·실무자 관점 메모`: `08_작성규칙/작성규칙.md` 1절 체크리스트를 이 공고에 맞춰 두세 줄씩.
4. `비공식 참고`: 에이전트 B 결과. 신뢰도 표시 유지.
5. `찾지 못한 것`을 빠뜨리지 않는다.

## 확인 1

사용자에게 보여 줄 것: 대응 표에서 "없음"인 요구, 고유 사실 목록, 찾지 못한 것. 공고가 AI 활용을 금지하면 맨 먼저 알리고, 초안 없이 얼개와 검사만 받을지 묻는다. 지원 이유를 모르면 묻고 답을 `01_나/나의말.md`에 저장한다. "아는 정보가 있으면 더해 주세요"라고 묻고 답을 파일에 반영한다. 답을 받기 전에는 2단계로 가지 않는다.
