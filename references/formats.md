# 산출물 양식

모든 파일은 `04_지원기업/<기업_직무>/`에 둔다. `MMDD`는 그 단계를 실행한 날.

## 1_공고_전형.md (입력)

```
# <기업> <채용명> — <직무>

- 접수: (기간, 포털)
- 근무지/고용형태:
- 주요 업무:
- 우대:
- 지원자격:
- 전형:
- 자소서 문항:
  1. <문항 원문> (제한 800자, 공백 포함)
  2. <문항 원문> (제한 1000바이트, 한글 2바이트)
- 인재상/핵심가치:
- 마감: YYYY-MM-DD HH:MM
- 출처: (공고 URL 또는 "사용자 제공 캡처 MMDD")
```

분량 단위를 모르면 입력 단계에서 바로 묻는다. 답을 받지 못한 채 진행해야 하면 `(제한 800자, 공백 포함 여부 미확인)`처럼 적고 1단계(조사)까지만 진행한 뒤 확인 1에서 다시 묻는다. 단위가 확정되기 전에는 3단계(초안)를 시작하지 않는다.

공고 원문 없이 요약만 받았으면 출처에 "사용자 요약 MMDD (공고 원문 아님)"으로 적고, 확인 1에서 원문(URL이나 캡처)을 요청한다.

## 2_기업분석_MMDD.md (조사)

```
# <기업> <직무> 조사 (MMDD)

## 공고 요구 × 장면 대응
| 공고 요구/우대 | 대응 장면 ID | 근거 강도(강/중/없음) | 메모 |

## 지원동기용 고유 사실 (3~5개, 모두 출처)
- 사실 — 출처 URL (확인 MMDD)

## 담당자·실무자 관점 메모
- 채용담당자가 이 공고에서 볼 것:
- 실무자가 이 직무에서 볼 것:

## 비공식 참고 (초안 근거로 쓰지 않음)
- 내용 — 출처 (신뢰도: 자칭 담당자/익명/플랫폼 공식)

## 찾지 못한 것
- 항목 — 어디를 찾았나
```

## 3_소재선택_MMDD.md (소재 + 얼개)

```
# 소재 선택 (MMDD)

## 문항 1: <문항 요약>
- 유형: (직무역량 | 문제해결 | 협업 | 갈등 | 실패 | 리더십 | 성장 | 지원동기 | 포부)
- 후보: CV-01 (이유), RT-02 (이유), SC-01 (이유)
- 추천: CV-01
- 각도: (장면의 `각도` 중 하나)
- 인재상: (대응하는 인재상·핵심가치 원문, 없으면 없음)
- 따른 구조: (레퍼런스 카드의 뼈대 이름)
- 메시지: (읽고 남아야 할 한 문장)
- 크게 쓸 순간: (순간 하나)
- 남길 사실: (목록. 500자 3~4개, 1000자 6~7개 기준)
- 뺄 사실: (목록. 비우지 않는다)
- 첫 문장 후보: ① ... ② ...
- 연결할 회사 고유 사실: (2_기업분석의 항목 번호, 없으면 없음)
- 기억 질문: (당시 글 인용 + 질문, 없으면 없음)

## 문항 2: ...

## 지원서 전체
- 중복 확인: 문항마다 장면이 다르다 (예/아니오)
- 한계를 쓸 문항: (1~2개)

## 사용자 확정
(사용자가 확정한 문항별 장면과 고친 내용. 비어 있으면 아직 확정 전)
```

## 유형별 레퍼런스 카드

3_소재선택의 `유형`으로 읽을 카드다. 카드는 `08_작성규칙/레퍼런스/`에 있다. 파일 이름이 유형 이름과 다른 것이 있으니 이 표를 따른다.

| 유형 | 카드 |
|---|---|
| 직무역량 | `직무역량.md` |
| 문제해결 | `문제해결.md` |
| 협업 | `협업.md` |
| 갈등 | `갈등_가치관.md` |
| 실패 | `실패.md` |
| 리더십 | 카드 없음. 팀을 이끈 장면이면 `협업.md`, 새로 맡은 자리면 `도전_변화.md`를 본다 |
| 성장 | 도전·변화를 묻는 문항은 `도전_변화.md`, 성장과정·가치관·자기소개를 묻는 문항은 `가치관_자기소개.md` |
| 지원동기 | `지원동기.md` |
| 포부 | `포부_비전.md` |

## 3_초안_MMDD.md (초안) — check.py가 읽는다. 글자 하나까지 지킨다.

```
# 초안 (MMDD)

## 문항 1: <문항 요약>
<!-- limit: 800, unit: chars, spaces: include, type: 직무역량 -->
### 본문
<문장들. 제출용 그대로. 줄바꿈은 문단 구분에만.>
### 근거
| 사실 | 장면 | 근거 | 유형 |
|---|---|---|---|
| 예산 300만 원 중 240만 원 | SC-02 | [원본: 정산서.xlsx:합계] | 사실 |
| 운영지원팀 | | 2_기업분석 고유 사실 1 | 사실 |
| 사람이 매일 쓰는 서비스 | | 나의말 | 제안 |

## 문항 2: ...
```

- `limit` 주석: `unit`은 `chars` 또는 `bytes`. `bytes`면 `hangul: 2` 또는 `hangul: 3`을 더한다. `spaces`는 `include` 또는 `exclude`. `type`은 3_소재선택의 유형(직무역량, 문제해결, 협업, 갈등, 실패, 리더십, 성장, 지원동기, 포부). check.py는 직무역량·문제해결에서만 수치 0개를 경고한다.
- `사실`은 본문에 그대로 있는 구절. 본문의 모든 숫자는 어느 행의 사실 칸에 있어야 한다.
- `근거`는 장면 칸의 근거 표시를 글자 그대로. 장면이 비면 `1_공고_전형`, `2_기업분석`, `사실원장`, `나의말`, `사용자 답변`으로 시작한다.
- `유형`은 `사실`, `제안`, `승인`. 뱅크에 없는 해석은 `제안`이고, 사용자가 승인하면 `승인`으로 바꾼다.
- 본문에는 근거 표시나 주석을 넣지 않는다.

```
|---|---|---|---|

### 문항 1 꼬리질문

3. ...

## 범용성 테스트
문항 1: 회사명을 <경쟁사>로 바꿔 읽음 → 말이 됨/안 됨. 이유: ...

## 수정 대상 요약
- 문항 N "구절": ...
```
